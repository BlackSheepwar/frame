# 2026-10-29

## BSP_SPI：SPI 通用 BSP 层（总线 + 设备两级句柄）

- 新增 `User/BSP/BSP_SPI/bsp_spi.h` 与 `bsp_spi.c`，风格对齐 `BSP_IIC`：
  互斥量排队 + DMA 完成中断唤醒（无 DMA 时自动退回 HAL 阻塞接口）。
- 两级不透明句柄：`bsp_spi_t`（一路外设一条总线一把锁）、`bsp_spi_dev_t`
  （总线 + 片选 + 极性），一条总线可挂多个设备。
- 方向能力在 `BSP_SPI_Init()` 时由 `hspi->Init.Direction` 推出并存 `caps`：
  2LINES → TX/RX/TXRX，1LINE → 仅 TX，2LINES_RXONLY → 仅 RX；不支持的
  方向在入参处直接返回 `BSP_SPI_ERR_MODE`。
- 设备实例：`bsp_spi2_dev_lcd`（CS = PA8，低有效）；为此在 `bsp_gpio.c`
  新增 `bsp_gpio_pa8`。
- 配置侧改动：`frame.ioc` 增加 `SPI_LOCK` 互斥量（Mutexes02），
  `freertos.c` 生成块补 `SPI_LOCKHandle` 创建，`USER CODE BEGIN RTOS_MUTEX`
  里加 `BSP_SPI_Init()`。
- CMake：`User/BSP/CMakeLists.txt` 加 `bsp_spi`（PRIVATE 链 stm32cubemx 与
  bsp_gpio），`User/CMakeLists.txt` 主目标链 `bsp_spi`。
- 验证：`build/verify` 用 STM32CubeCLT 的 cmake/ninja + gcc 13.3.1 编译通过
  （-Werror 无警告），RAM 11544B / FLASH 45224B。
- 决策：用户只做主设备，已删掉从机相关的一切。`BSP_SPI_Init()` 里
  `hspi->Init.Mode != SPI_MODE_MASTER` 直接返回 `BSP_SPI_ERR_STATE`；
  不再有 `is_master` 字段与传输期判定，注释里的从机文案全部清掉。
  方向能力（TX/RX/TXRX）保留，那是主机的三种工作模式。
- 注意：`build/Debug` 的缓存仍指向旧路径 `d:/a1/Project/frame`，工程移动过
  目录，需要重新 Configure 才能用。

## 接口精简（当日第二轮）

- 对外传输入口收敛为两个：`BSP_SPI_Transfer(bus, tx, rx, len, timeout_ms)`
  （不管片选）与 `BSP_SPI_Dev_Transfer(dev, tx, rx, len, timeout_ms)`
  （自动拉放片选）。方向由指针推断：tx 有 rx 无=只发，tx 无 rx 有=只收，
  两者都有=全双工，都没有=ERR_PARAM。
- 删掉 `BSP_SPI_Write/Read/WriteRead`、`BSP_SPI_Dev_Write/Read/WriteRead`
  以及公共头文件里的 `bsp_spi_msg_t` / `bsp_spi_dir_t`；两者改为 .c 内部类型。
- 删掉 `cs_hold` 字段：一帧多段发、片选保持低的场景改为
  `BSP_SPI_Dev_Select()` + 若干次 `BSP_SPI_Transfer()` + `Deselect()`。
- `BSP_SPI_CAP_TXRX` / `BSP_SPI_DMA_TXRX` 改为组合宏 `(TX | RX)`，不再占
  独立位；能力检查相应改成 `(caps & need) == need`（必须全含）。
- 编译验证：`-Werror` 无警告，RAM 11544B / FLASH 45224B（与精简前一致，
  gc-sections 把删掉的包装函数去掉了）。
